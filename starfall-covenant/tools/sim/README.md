# 流派模擬器

讓每個流派的自動轉珠 AI 打關卡上千次，輸出各流派的勝率與平均通關回合，用來調整卡片與關卡數值（GDD 2.0「平衡工具」）。

```bash
npm run sim                                # 12 流派 × 全部基準關卡，每格 20 場
npm run sim -- --runs 50 --stage sim-armor # 只跑一關
npm run sim -- --archetype combo --json out.json
```

## 怎麼運作
- `strategies.ts`：12 個流派各一種策略，寫明「這個流派想把盤面轉成什麼樣子」（例：連擊＝多組 3 顆、長串＝一大串、背水＝高血量時不補血）。
- `planner.ts`：束搜尋找拖曳路徑。每條路徑用戰鬥模組的隊長技、傷害、回復公式算出實際效果，再加上流派偏好分數。路徑長度受轉珠時間限制（預設每秒 4 格），延長轉珠時間的效果會自然反映在結果上。
- `skills.ts`：主動技施放策略。進攻類技能好了就放；減傷、延遲等防守技能等敵人要出手或血量低於一半才放；回復、解除異常看血量和身上的狀態；自損技能放完後血量要夠安全（背水隊例外）；冷卻縮減最先放。技能循環流派任何技能好了就放。規劃器也會把主動技 buff、回復轉攻擊、敵人護盾、心珠封印與不能消除的珠種算進分數。
- `simulate.ts`：跑單場戰鬥、跑「流派 × 關卡」矩陣、找出超出 ±20% 平衡目標或打不過的組合、輸出 Markdown 報表。
- `fixtures/`：正式卡片與關卡資料寫進 `data/` 之前的暫定資料。
  - `proposal-001.json`：提案 001（總監已通過）的 43 位角色、主動技、隊長技與第 8 節的免抽入門隊。數值依稀有度給暫定值；尚未核准進 types.ts 的新積木先略過。
  - `benchmark.json`：5 個基準關卡（標準三波、小怪海、高防禦、高血量首領、高攻擊）。

## 目前的限制
- 主動技已經接上（見 `reports/2026-10-30-skills.md`）。施放時機對結果影響不大，強化珠、控場、技能循環偏慢主要是暫定數值的問題（例如技能循環免抽隊長 c409 只有開場充能、沒有攻擊倍率）。
- 提案 001 的 3 個新積木只出現在進化後的卡（c303、c403、c412），暫定資料目前沒有這些卡，正式資料寫進 `data/` 後就會用到。
- AI 只看轉珠當下的第一層消除，不預測天降。
