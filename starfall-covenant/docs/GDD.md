# 《星骸契約》遊戲設計規格書 v0.2（草案，已擴大 v0.1 範圍）

> 類型：轉珠消除 × 卡牌養成 RPG｜平台：HTML5 網頁遊戲（手機直式優先）｜狀態：待使用者確認

> 原創聲明：本作所有角色、名稱、世界觀、美術、劇情皆為原創。只沿用「轉珠消除＋卡牌養成」這類遊戲的通用玩法，不使用任何既有作品的角色、名稱、美術、劇情或專有用語。

## 1. 世界觀（推薦方案）

**名稱：《星骸契約》（Starfall Covenant）**

很久以前，天穹上的「七曜星座」在一場無人記得的戰爭中碎裂，碎片如雨墜落大地，化為帶有意志的「星骸」。星骸會汙染土地、扭曲生物，形成名為「墜域」的危險地帶。

人類中少數能讀懂星紋的人被稱為「契印師」。他們以星紋珠為媒介，與星骸中殘存的英靈「星靈」締結契約，借用其力量淨化墜域、收集碎片，並在過程中逐步揭開：星座當年為何碎裂？是誰把它擊碎的？

玩家扮演一名剛覺醒的見習契印師，從邊境小鎮「灰燈港」出發，一路前往漂浮在雲層上的星座遺跡「穹頂」。

**為什麼推薦這個：**
- 「收集墜落的星靈」天然對應抽卡與收集，「讀懂星紋」天然對應轉珠玩法，系統和故事能互相解釋。
- 星座題材可以無限擴充（每個星座是一個章節、一個種族、一批角色），適合長期營運。
- 與既有作品的「神／魔／塔」母題完全不同，避免撞名或撞設定。

### 1.1 屬性（五屬＋心）

| 屬性 | 名稱 | 星紋珠 | 剋制 |
|---|---|---|---|
| 火 | 焰 | 焰紋珠（紅） | 焰 → 森 |
| 水 | 潮 | 潮紋珠（藍） | 潮 → 焰 |
| 木 | 森 | 森紋珠（綠） | 森 → 潮 |
| 光 | 輝 | 輝紋珠（金） | 輝 ⇄ 蝕 互剋 |
| 暗 | 蝕 | 蝕紋珠（紫） | 蝕 ⇄ 輝 互剋 |

### 1.2 種族（星靈的出身）

六種族，對應六個初始星座：**獸裔**（獸座）、**龍嗣**（龍座）、**機構**（工匠座）、**靈仙**（羽座）、**冥裔**（冥河座）、**人傑**（英雄座）。種族供隊長技、主動技指定加成使用，並另設「進化素材」「強化素材」兩種非戰鬥卡種。

### 1.3 初期角色規劃（v0.1 共 84 張卡片資料，詳見 card-matrix.md）
- 每屬性 12 張戰鬥卡（含進化後型態）：
  - 6★ 限定 1 張（只出現在限定卡池）
  - 5★ 2 張（可進化為 6★ 型態 ⇒ 另計 2 個卡號）
  - 4★ 3 張、3★ 2 張（3★ 可進化為 4★ ⇒ 另計 2 個卡號）
  - 合計每屬性 12 ＝ 60 張戰鬥卡，另加 4 張活動／挑戰之塔／章節獎勵的 4★ 種族隊長
- 素材卡 20 張：每屬性「星塵靈」強化素材 ×3 階、進化素材「星核」×1（共 20）
- 另有約 40 種敵人（含 10 隻章節 Boss、5 隻活動 Boss）
- 角色名稱、外觀、背景由「創意顧問」提案，總監審核後寫入資料檔。

## 2. 系統清單

### 2.0 卡片流派（本作核心）

本作最重要的樂趣是**「組出自己的流派」**：同樣一盤珠，不同隊伍會想用完全不同的轉法。每張卡片設計時都要先決定它屬於哪個流派、在流派裡扮演什麼角色，而不是單純比數值。

#### 設計原則
1. **流派決定轉法**：每個流派要讓玩家「轉珠的目標」明顯不同（湊 Combo、湊長串、湊多屬性、留心珠……），而不只是倍率不同。
2. **隊長＋核心＋輔助**：每個流派至少有 1 張隊長卡（定義規則）、2 張以上核心卡（主動技或覺醒讓流派成形）、2 張以上輔助卡（可跨流派通用）。
3. **入門一定拿得到**：每個流派至少有 1 套「免抽卡」組合（關卡掉落、活動兌換、挑戰之塔獎勵），抽卡只是讓流派更強、更順，不是門票。
4. **沒有萬用最強**：每個流派都有明確弱點，關卡與敵人技能會輪流考驗不同流派（例：Combo 盾考驗低 Combo 隊、屬性減傷考驗單屬隊、高防禦考驗低攻擊的續航隊），讓玩家有理由練第二、第三套隊伍。
5. **跨流派混搭**：卡片帶「流派標籤」，部分卡同時屬於兩個流派，鼓勵玩家發明混合打法（例：龍嗣種族＋高 Combo）。
6. **數值基準**：以「同等投入下，各流派在其擅長關卡的通關回合數差距不超過 ±20%」為平衡目標；平衡由關卡與經濟負責人用模擬器驗證（見下）。

|---|---|---|---|---|---|

| 12 | **固定傷害** | 不看攻擊力，造成固定傷害 | 每消除 1 組心珠追打固定傷害 | 真實傷害、無視護盾 | 生命極高的 Boss |

#### 卡片在流派中的角色
- **隊長**：定義流派規則。每流派 1–2 張，通常是 5★／6★，另有 1 張 4★「平民隊長」。
- **核心**：讓流派運轉的主動技或覺醒（例：七彩齊攻的「補缺色」）。
- **輔助**：通用的回血、減傷、延遲、轉珠，可放進多個流派。
- **素材**：不屬於流派。

#### 資料格式
卡片加入流派欄位（`cards.json`）：
```json
"archetypes": [
  { "id": "combo", "role": "leader" },
  { "id": "race-dragon", "role": "core" }
]
```
另設 `data/archetypes.json` 描述每個流派的名稱、說明、推薦卡片、入門取得路徑，供遊戲內「流派圖鑑」與隊伍編成的「推薦搭配」使用。

#### 遊戲內呈現
- **流派圖鑑**：列出 12 個流派、玩法說明、你已擁有哪些卡、還缺哪些、去哪裡拿。
- **隊伍編成提示**：依隊長自動顯示目前隊伍屬於哪個流派、流派完成度、哪些成員不搭。
- **關卡情報**：進關前顯示「推薦流派」與敵人特性，讓玩家知道該換哪套隊伍。

#### 平衡工具
- `tools/sim/`：戰鬥模擬器，用簡單的 AI 轉珠策略（每個流派一種策略）自動跑關卡上千次，輸出各流派的平均通關回合與勝率，用來調整卡片與關卡數值。
- 新卡或改數值的 PR 都要附上模擬結果。

### 2.1 核心轉珠戰鬥（Battle）
- **盤面**：6 欄 × 5 列，6 種珠。
- **操作**：手指按住任一珠拖曳，拖過的珠會與手上的珠交換位置；拖曳時限預設 5 秒（第一次移動後開始倒數），放手或時間到即結算。可斜向移動。
- **消除規則**：同色橫或直連 3 顆以上消除；相連的同色組合（L、T、十字）算同一個 Combo。消除後上方珠落下、從上方補新珠（天降），天降造成的再消除也計入 Combo。
- **傷害公式**（每位隊員）：
  `基礎 = 角色攻擊 × (1 + 0.25 × (該屬性消除珠數 − 3)) × 該屬性消除組數`
  `總傷 = 基礎 × (1 + 0.25 × (Combo − 1)) × 隊長技倍率 × 屬性剋制 × 其他加成`
  ‑ 一次消除 5 顆以上同色珠＝「全體攻擊」，否則單體攻擊目標敵人。
  ‑ 心珠回復量 = 全隊回復力總和 × 同上的珠數與 Combo 倍率。
- **隊伍**：5 名自己的卡＋1 名「助戰」（v0.1 為 NPC 助戰，之後可接好友系統），第 1 位是隊長、助戰是副隊長，兩者的隊長技同時生效。隊伍生命＝所有隊員生命總和。
- **敵人**：有生命、攻擊、防禦、屬性、攻擊倒數（CD）。玩家每轉一次珠 CD −1，歸零時攻擊並重置。敵人可帶「敵人技能」（例：開場護盾、屬性減傷、連擊、珠子變化）。
- **主動技**：每張卡一個，有冷卻回合數，冷卻滿可在轉珠前點擊施放（例：轉珠、單體大傷、回血、減傷、延長轉珠時間）。
- **隊長技**：條件＋效果（例：「焰屬性攻擊力 ×2.5」「Combo ≥ 6 時全隊攻擊 ×3」）。
- **關卡流程**：一個關卡有多波敵人（1–5 波），清空一波進下一波；最後一波為 Boss。隊伍生命歸零則失敗，可用星晶「續戰」（回滿生命、清除負面狀態）。
- **強化珠**：特定技能可把珠子變成「強化珠」（消除時傷害 +15%）；另有「封鎖珠」「毒珠」等敵人造成的干擾珠。
- **異常狀態**：中毒、封印主動技、珠子鎖定、轉珠時間縮短、敵方護盾、屬性減傷、Combo 數門檻護盾。
- **結算**：顯示獲得經驗、金幣、掉落卡片、首通獎勵。

### 2.2 卡片養成（Growth）
- **稀有度**：1★–6★（v0.1 用到 5★）。稀有度決定等級上限與成長曲線。
- **等級**：吃「強化素材」或其他卡片獲得經驗。同屬性素材經驗 ×1.5。強化消耗金幣。
- **進化**：等級滿後，消耗指定進化素材＋金幣，進化成更高型態（新卡號，保留技能等級）。
- **技能升級**：吞同名卡或指定技能素材，主動技 CD −1（有上限）。
- **突破**：吞同名卡提升能力上限（最多 +5 階），每階提升基礎數值。
- **星紋覺醒**：每張 5★ 以上有 3 個被動（例：焰珠傷害 +5%、轉珠時間 +0.5 秒），消耗同屬星核與金幣逐一解鎖；第 1 個不需突破，第 2、3 個分別需要突破 +3、+5，讓只有一張的卡也能先體驗流派特色。
- **背包**：卡片數上限（初始 50，可用星晶擴充 +5）、上鎖保護、排序與篩選（屬性、種族、稀有度、等級）。
- **圖鑑**：已見／已擁有的卡片列表，第一次擁有給星晶獎勵。

### 2.3 關卡與經濟（Progression & Economy）
- **主線關卡**：章節 → 關卡（每章 8 關＋1 Boss 關），需通過前一關解鎖；每關有 3 個「星章」挑戰條件（例：5 回合內通關、不使用主動技、隊伍只含焰屬性），集滿章節星章領獎。v0.1 做 5 章共 45 關。
- **每日關卡**：週一到週日輪替屬性的素材關與進化素材關，週末開金幣關。
- **活動關卡**：以資料檔定義開放時間，含活動專屬 Boss 與兌換商店（v0.1 內建 1 個活動）。
- **挑戰之塔**：無體力消耗的連續樓層挑戰，每 10 層給星晶，共 30 層，難度逐層升高。
- **體力**：每關消耗 3–15 點；每 5 分鐘回 1 點（依真實時間，離線也算）；升級時全回並提高上限；可用星晶補滿。
- **玩家等級**：打關卡獲得玩家經驗，升級提高體力上限與隊伍「隊伍空間（Cost）」上限。
- **貨幣**：
  - 金幣：強化、進化花費；關卡掉落、販賣卡片取得。
  - 星晶（付費貨幣，本作僅遊戲內取得、不接真實付款）：抽卡、補體力、擴背包、續戰。來源：首通、玩家升級、圖鑑、每日登入。
- **召喚（抽卡）**：
  - 星晶 5 顆抽 1 次；10 連抽保底 1 張 4★ 以上。
  - 基本機率：5★ 3%｜4★ 17%｜3★ 80%。
  - 保底：連續 80 抽沒有 5★ 時，下一抽必出 5★（計數存在存檔）。
  - 卡池以資料檔定義，可做「限定卡池」並在畫面上公開機率。
- **商店**：用星晶補體力、擴背包；用金幣買素材（每日限購）。
- **每日登入**：7 日循環獎勵。
- **任務／成就**：每日任務（例：轉出 10 Combo、打 3 關）、每週任務、成就（約 50 項）。
- **好友助戰**：單機版用 NPC「流浪契印師」名單模擬好友（每天輪替、帶不同隊長），之後接後端再換成真人。

### 2.4 存檔（Save）
- 單機遊戲，存在瀏覽器 `localStorage`，每次關鍵操作（戰鬥結算、抽卡、強化、購買）後立即存檔。
- 存檔帶版本號，讀檔時依版本跑遷移函式。
- 提供「匯出存檔碼／匯入存檔碼」（Base64 JSON），讓玩家換手機或備份。
- 防呆：存檔帶簡易校驗碼，避免手動改壞後當機（不追求防作弊）。
- 之後若要雲端存檔或排行榜再另外規劃後端。

### 2.5 介面（UI）
- 直式畫面，以 **390 × 844** 為設計基準，等比縮放；盤面在下半部方便單手拖曳；支援瀏海安全區。
- 畫面清單：
  1. 標題／載入
  2. 主城（主選單：冒險、隊伍、卡片、召喚、商店、設定）
  3. 章節地圖 → 關卡列表 → 選助戰 → 戰鬥前確認
  4. 戰鬥（上：敵人區；中：隊伍頭像＋生命條；下：6×5 盤面）
  5. 結算
  6. 隊伍編成（多組隊伍切換）
  7. 卡片背包／卡片詳情／強化／進化
  8. 召喚（卡池、機率說明、抽卡演出）
  9. 商店、每日登入
  10. 設定（音量、轉珠時間顯示、存檔匯出匯入）
  11. 新手教學（前 3 關強制引導轉珠與 Combo）

### 2.6 美術與音效
- **風格**：夜空藍底色＋星光金點綴，扁平繪本風；卡框依稀有度分色。
- **初期素材策略**：v0.1 全部用程式產生或簡單 SVG（屬性色塊＋圖示＋名字縮寫的卡面、幾何形狀的珠與敵人），先確保玩法完整；正式立繪之後再分批替換，資料格式預留圖片路徑欄位。
- **珠子**辨識不只靠顏色，每種珠都有不同符號（照顧色弱玩家）。
- **音效**：消除音隨 Combo 升高音階；v0.1 用 Web Audio 產生簡單音效，BGM 之後補。

## 3. 技術架構

- **語言／工具**：TypeScript ＋ Vite（打包）＋ Vitest（單元測試）。不使用大型遊戲引擎，降低學習門檻。
- **繪圖**：戰鬥盤面與特效用 Canvas 2D；選單介面用 DOM＋CSS（好排版、好維護）。
- **輸入**：Pointer Events 統一處理觸控與滑鼠，桌機也能測試。
- **發佈**：GitHub Pages（push 到 main 自動部署），手機直接開網址遊玩；之後可加 PWA 讓玩家「加到主畫面」。
- **核心原則**：遊戲規則（戰鬥計算、抽卡、經濟）寫成**純邏輯模組，不碰畫面**，才能寫測試、也方便之後換畫面技術。

### 3.1 目錄結構

```
/
├─ index.html
├─ src/
│  ├─ main.ts                 進入點、畫面路由
│  ├─ core/                   共用：事件匯流排、亂數（可設種子）、時間、型別
│  ├─ battle/                 【核心轉珠戰鬥】
│  │  ├─ board.ts             盤面、消除判定、天降（純邏輯）
│  │  ├─ damage.ts            傷害／回復計算（純邏輯）
│  │  ├─ battle-state.ts      戰鬥狀態機：轉珠 → 結算 → 敵人行動 → 下一回合
│  │  ├─ skills/              主動技、隊長技、敵人技能的效果實作
│  │  └─ view/                Canvas 繪製、拖曳輸入、特效
│  ├─ growth/                 【養成】強化、進化、技能升級、背包
│  ├─ progression/            【關卡與經濟】關卡解鎖、體力、獎勵、抽卡、商店、登入
│  ├─ save/                   【存檔】讀寫、版本遷移、匯出匯入
│  ├─ ui/                     【介面】各畫面、共用元件、主題樣式
│  └─ data/                   資料讀取與驗證（讀下方 JSON）
├─ data/                      【遊戲資料，全是 JSON】
│  ├─ cards.json  skills.json  leader-skills.json
│  ├─ enemies.json  stages.json  gacha-pools.json
│  └─ shop.json  login-rewards.json  config.json
├─ assets/                    圖片、音效
├─ tests/                     單元測試
└─ docs/                      設計文件（本規格書、各提案）
```

### 3.2 資料格式（JSON）

**卡片 `cards.json`**
```json
{
  "id": "c0001",
  "name": "（創意顧問命名）",
  "attribute": "fire",            // fire | water | wood | light | dark
  "race": "beast",                // beast | dragon | machina | sylph | nether | human | material
  "rarity": 4,
  "maxLevel": 70,
  "stats": { "hp": [800, 2400], "atk": [300, 1050], "rcv": [100, 320] },  // [Lv1, LvMax]
  "growthCurve": 1.0,             // 成長曲線指數
  "cost": 8,                      // 隊伍空間
  "activeSkill": "s0001",
  "leaderSkill": "l0001",
  "evolution": { "to": "c0002", "materials": ["c0901", "c0901"], "coin": 5000 },
```

**主動技 `skills.json`**（效果用「效果積木」組合，避免每個技能都寫程式）
```json

  "cooldown": { "max": 12, "min": 6 },

    { "type": "convertOrbs", "from": "water", "to": "fire" },
```

## 5. 分工與審核流程

所有工作在 GitHub repo 以 Pull Request 進行，**每個 PR 都要總監審核通過才合併**。創意顧問的提案以 `docs/proposals/` 的文件形式提交，同樣經總監審核。

| 角色 | 負責模組 | 第一批工作 | 依賴 |
|---|---|---|---|
| **總監** | 全局、`core/`、`data/` 驗證、**流派總表** | 建立專案骨架（Vite＋TS＋Vitest＋Pages 部署）、型別定義、資料讀取與驗證；維護流派總表（docs/card-matrix.md）；審核全部 PR | — |
| **核心轉珠戰鬥** | `battle/` | 盤面與消除判定 → 傷害計算 → 戰鬥狀態機 → 主動技／隊長技積木 → Canvas 拖曳與動畫 | 骨架、型別 |
| **養成系統** | `growth/` | 強化、進化、技能升級、突破、星紋覺醒、背包、圖鑑（純邏輯＋測試） | 骨架、型別、存檔介面 |
| **關卡與經濟** | `progression/`、`save/` | 存檔與遷移 → 體力 → 關卡解鎖與獎勵 → 召喚與保底 → 商店、登入、任務、成就、活動、挑戰之塔；並填寫全部關卡資料；建立 `tools/sim/` 戰鬥模擬器做流派平衡 | 骨架、型別 |
| **介面與美術** | `ui/`、`assets/` | 主題樣式、共用元件、全部畫面、劇情對話框、整理使用者提供的美術音樂、程式產生不足的素材、音效與 BGM 播放 | 各系統的公開函式介面 |
| **創意顧問** | `docs/proposals/`、卡片與劇情文字 | 依流派總表提案 63 張戰鬥卡的技能組合與角色設定（名稱、外觀、背景、技能命名），素材卡命名；5 章劇情腳本；約 40 種敵人與活動設定 | 世界觀（本文件） |

**進行順序**
1. 總監先完成骨架與型別（約 1 個 PR），讓其他人有共同基礎。
2. 戰鬥、養成、關卡經濟、創意顧問**同時開工**（彼此只透過型別和資料溝通）。
3. 介面與美術先做主題與共用元件，接著依各系統完成度串接畫面。
4. 全部串好後由總監做整合測試，發佈 v0.1 到 GitHub Pages。

### 2.7 使用者提供的美術與音樂素材
- 放在 `assets/user/` 下，依類型分 `cards/`、`enemies/`、`backgrounds/`、`ui/`、`bgm/`、`sfx/`。
- 每批素材附一份 `assets/user/CREDITS.md` 記錄來源與授權，確認可以用在本遊戲。
- 介面與美術負責人會整理檔名、壓縮尺寸（圖片轉 WebP、音樂轉 OGG/MP3），並在資料檔的 `art` 欄位指向這些檔案。
