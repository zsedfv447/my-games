# 分工說明與審核流程

## 共同規則
- 每個分工在自己的分支開發（`claude/<分工>-<主題>`），完成一個可測試的段落就開 PR 到 `main`。
- **所有 PR 都要總監審核後才合併。** 創意顧問的提案放 `docs/proposals/`，同樣以 PR 送審。
- 只改自己負責的資料夾。需要改 `src/core/types.ts` 或別人的模組時，在 PR 說明裡寫清楚原因，由總監決定。
- 遊戲規則一律寫成**純邏輯**（不碰 DOM／Canvas），並附 Vitest 測試；`npm test` 和 `npm run build` 必須通過。
- 隨機一律用 `src/core/rng.ts`，方便重現與模擬。
- 文字一律繁體中文；所有角色、名稱、美術皆為原創，不得使用任何既有作品的角色、名稱、美術或劇情。

## 1. 核心轉珠戰鬥 — `src/battle/`
1. `board.ts`：依 `config.board` 建立盤面、交換路徑、消除判定（橫直 3 顆以上、相連同色合併為一組）、天降補珠、強化珠與干擾珠。
2. `damage.ts`：GDD 2.1 傷害公式、屬性剋制、全體攻擊、心珠回復、防禦與護盾。
3. `leader.ts`：解析 `LeaderSkillDef`（條件＋效果），計算本回合倍率；隊長與助戰兩個隊長技相乘。
4. `skills/`：`SkillEffect` 全部 20 種效果積木；敵人異常狀態 15 種。
5. `battle-state.ts`：回合狀態機（施放主動技 → 轉珠 → 結算 → 敵人行動 → 換波／勝敗）、續戰。
6. ~~`view/`~~：已移交介面與美術（見第 4 節）。戰鬥組負責提供足夠的事件與狀態快照，讓畫面能播放動畫。
- 介面：對外提供 `startBattle(stage, team, helper, rng)` 與事件，讓介面與關卡模組呼叫。

## 2. 養成系統 — `src/growth/`
強化（經驗、同屬加成、金幣）、進化、技能升級、突破、星紋覺醒、背包（上鎖、排序、篩選、擴充、批次販賣）、圖鑑與收集獎勵。全部是操作 `SaveData` 的純函式，回傳新狀態或錯誤原因。

## 3. 關卡與經濟 — `src/progression/`、`src/save/`、`tools/sim/`、`data/stages.json` 等
1. `save/`：讀寫 localStorage、版本遷移、校驗碼、匯出匯入存檔碼、重置。
2. 體力（真實時間回復）、玩家等級、關卡解鎖、星章、獎勵與掉落。
3. 召喚（常駐／限定池、單抽、十連保底、80 抽保底、抽卡紀錄）、商店、7 日登入、任務與成就、活動與兌換、挑戰之塔。
4. 關卡資料：5 章 45 關、7 種每日關卡、1 個活動、30 層塔；每關標註 `recommendedArchetypes`，輪流考驗不同流派。
5. `tools/sim/`：戰鬥模擬器，每個流派一種自動轉珠策略，輸出各流派通關回合與勝率。

## 4. 介面與美術 — `src/ui/`、`assets/`
戰鬥畫面整體由介面組負責，包含 `src/battle/view/`：Canvas 盤面繪製、Pointer Events 拖曳（可斜向、軌跡顯示、倒數計時）、消除與傷害動畫；只透過 `battle-state.ts` 的 `startBattle` 介面與事件操作戰鬥。
主題與共用元件、畫面路由、GDD 2.5 全部畫面＋任務、成就、圖鑑、流派圖鑑、活動、挑戰之塔、劇情對話、抽卡紀錄；新手教學；程式產生的卡面、珠子（含色弱符號）、敵人；使用者提供素材的整理（`assets/user/`，並更新 `CREDITS.md`）；BGM 與音效播放；PWA。

## 5. 創意顧問 — `docs/proposals/`、`data/` 文字欄位
依 `docs/card-matrix.md`：43 位角色（63 張戰鬥卡）的名稱、種族、外觀、背景、主動技與隊長技設計（用 types.ts 的效果積木表達）、素材卡命名；約 40 種敵人；5 章劇情腳本與 1 個活動劇情。提案通過後寫入 `data/*.json`。

## 依賴與順序
1. 本骨架合併後，戰鬥、養成、關卡經濟、創意顧問同時開工。
2. 介面先做主題、共用元件與畫面路由，再依各系統進度串接。
3. 全部串好後由總監整合測試並發佈 v0.1。
